Preparing & Building the Frontend Bundle

Before uploading your frontend to any server, Vite must compile your JSX, Tailwind utilities, and JavaScript modules into an ultra-compressed static bundle. Follow these crucial steps:

1

Configure Production API URL

In local development, Vite proxies /api to http://127.0.0.1:8000. In production, decide whether your API will live on:

  • Subdomain: e.g. https://api.yourdomain.com/api (common for Vercel/Netlify frontend + Cloud API).
  • Same Domain Path: e.g. https://yourdomain.com/api (common on VPS Nginx with reverse proxy).

Create or verify frontend/.env.production:

frontend/.env.production 
# If API is on a separate subdomain or server:
VITE_API_BASE_URL=https://api.yourdomain.com/api

# If API is reverse-proxied on the same domain (e.g. Nginx on VPS):
# VITE_API_BASE_URL=/api
2

Run Vite Production Build

In your terminal, navigate to the frontend/ directory and compile:

Bash 
cd /home/farouk/development/frontend
npm run build
💡
What happens? Vite processes all React files, purges unused Tailwind CSS, optimizes images, and outputs everything into the frontend/dist/ folder. This folder contains index.html, assets/*.js, and assets/*.css.
3

Test the Production Build Locally

Always verify the compiled production build on your machine before uploading to a server:

Bash 
npm run preview
# Vite will launch a production server at http://localhost:4173

Method A: Deploy to Vercel or Netlify (Zero Server Maintenance)

Deploying to Vercel or Netlify gives you global CDN caching, automatic SSL, and instant rollbacks. Here is exactly how to do it:

🚀 Deploying to Vercel in 3 Steps

Step 1: Add SPA Rewrite Configuration (vercel.json)

To prevent 404 errors when a customer refreshes a page on a React client-side route, create a vercel.json file in your frontend/ directory:

frontend/vercel.json 
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}

Step 2: Deploy via Vercel CLI (or Git)

Bash 
# Install Vercel CLI globally (one time)
npm install -g vercel

# Navigate to frontend folder and deploy
cd /home/farouk/development/frontend
vercel

# When prompted:
# ? Set up and deploy "~/development/frontend"? [Y/n] y
# ? Which scope do you want to deploy to? (Select your account)
# ? Link to existing project? [y/N] n
# ? What's your project's name? novacart-store
# ? In which directory is your code located? ./
# ? Want to modify these settings? N

# Deploy to production:
vercel --prod

Step 3: Connect Custom Domain

Go to Vercel Dashboard → Your Project → Settings → Domains, add yourdomain.com, and point the CNAME / A records in your DNS provider (Cloudflare, Namecheap, GoDaddy).

💎 Deploying to Netlify

Step 1: Add SPA Redirect Rule (_redirects)

Create a file named frontend/public/_redirects so Netlify always serves index.html:

frontend/public/_redirects 
/*    /index.html   200

Step 2: Drag & Drop Method (No Git required)

  1. Run npm run build inside the frontend/ directory.
  2. Log in to app.netlify.com.
  3. Drag the entire dist/ folder into the "Sites" drag-and-drop zone.
  4. Your store will be live in 5 seconds with a free https://*.netlify.app URL!

Method C: Linux VPS Deployment (Ubuntu / Nginx / Reverse Proxy)

If you want to host both the React frontend and the PHP backend on the same Ubuntu server ($4-$6/mo on Hetzner, DigitalOcean, or Linode), this is the cleanest, professional enterprise setup.

🛠️ Step-by-Step VPS Architecture

1. Upload the built dist/ folder to your server:

Bash (Run on your local machine) 
# 1. Build locally
cd /home/farouk/development/frontend
npm run build

# 2. Upload dist/ to VPS via rsync
rsync -avz --delete dist/ user@YOUR_SERVER_IP:/var/www/novacart/frontend/dist/

2. Production Nginx Configuration:

This configuration serves the compiled React app with SPA fallback routing, enables Brotli/Gzip compression, sets high-performance caching for static assets, and proxies /api/ requests to the PHP 8.4 backend on port 8000 (or PHP-FPM socket):

Nginx (/etc/nginx/sites-available/novacart.conf) 
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yourdomain.com www.yourdomain.com;

    # SSL Certificates (managed automatically by Certbot)
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # Gzip Compression
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml text/javascript image/svg+xml;

    # 1. Frontend: React Static Files
    root /var/www/novacart/frontend/dist;
    index index.html;

    # Security Headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # SPA Routing: Fallback all client routes (e.g. /products, /cart) to index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Static Assets Cache (1 year immutable)
    location ~* \.(?:css|js|woff2?|svg|gif|png|jpe?g|webp|ico)$ {
        expires 1y;
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
    }

    # 2. Backend: Proxy /api requests to PHP 8.4 API Server
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Rate Limiting & Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}

3. Enable site and install free SSL certificate with Let's Encrypt:

Bash (On VPS) 
# Enable site
sudo ln -s /etc/nginx/sites-available/novacart.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

# Install Certbot and obtain free SSL certificate
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

Method D: Shared Hosting / cPanel Deployment (Apache .htaccess)

📁 Uploading to cPanel File Manager or FTP

If you are using shared hosting (e.g. Hostinger, Namecheap, Bluehost, cPanel), you must configure Apache's .htaccess file to route all URL paths through index.html so React Router doesn't return a 404 error when refreshing pages.

Steps to Upload:

  1. Run npm run build on your computer inside frontend/.
  2. Enter the frontend/dist/ folder and compress all its contents into a dist.zip file.
  3. Log into cPanel → Open File Manager → Navigate to public_html/ (or your domain's document root).
  4. Upload dist.zip and click Extract directly inside public_html/.
  5. Create or edit the .htaccess file inside public_html/ with the rules below:
public_html/.htaccess 

  RewriteEngine On
  RewriteBase /

  # HTTPS Enforcement
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

  # Don't rewrite actual files or directories
  RewriteCond %{REQUEST_FILENAME} -f [OR]
  RewriteCond %{REQUEST_FILENAME} -d
  RewriteRule ^ - [L]

  # Route all other URLs to index.html (SPA Fallback)
  RewriteRule ^ index.html [L]


# Caching optimization

  ExpiresActive On
  ExpiresByType image/jpg "access plus 1 year"
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/gif "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"

Wiring Frontend to Backend & Solving CORS in Production

When your React frontend is hosted on one domain (e.g. https://novacart.com or https://novacart.vercel.app) and your PHP API is hosted on another (e.g. https://api.novacart.com), the browser strictly enforces Cross-Origin Resource Sharing (CORS).

🛡️ Configuring CORS in PHP 8.4 Backend

NovaCart's PHP backend has a built-in security layer that validates the request's Origin header against an allowed whitelist. Open your backend/.env on your production server:

backend/.env 
# Add your production frontend domain(s) separated by commas:
CORS_ALLOWED_ORIGINS=https://novacart.com,https://www.novacart.com,https://novacart.vercel.app,http://localhost:5173
⚠️
SSL / Mixed Content Warning: If your frontend is on https://, your backend API MUST also be on https://! Modern browsers will block any HTTP API request made from an HTTPS website with a Mixed Content Error.

Automated Deployments: GitHub Actions CI/CD Pipeline

Never manually run builds or FTP files again! Create this GitHub Action workflow so every time you git push origin main, GitHub automatically runs tests, builds your frontend, and deploys it.

.github/workflows/deploy-frontend.yml 
name: Deploy NovaCart Frontend

on:
  push:
    branches: [ main ]
    paths:
      - 'frontend/**'

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json

      - name: Install Dependencies
        run: |
          cd frontend
          npm ci

      - name: Build Production Assets
        env:
          VITE_API_BASE_URL: ${{ secrets.PROD_API_BASE_URL }}
        run: |
          cd frontend
          npm run build

      # Deploy step (example for Cloudflare Pages or Vercel)
      - name: Deploy to Cloudflare Pages
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          command: pages deploy frontend/dist --project-name=novacart-store

The Master Guide: Product Photos & Profile Pictures (PFPs) Uploads

eCommerce websites have strict requirements for media. Product photos must be high-resolution, multi-angle, fast-loading, and responsive. User Profile Pictures (PFPs) must be square, face-centered, lightweight, and strictly protected so users can only modify their own avatar.

🛍️ Product Photos Requirements
  • Database Schema: Stored in products.images as a JSONB array of URLs (e.g. ["https://...", "https://..."]).
  • Aspect Ratio: Consistent 1:1 (Square: 800x800px or 1000x1000px) or 4:3.
  • Max Upload Size: 2 MB per image after client compression.
  • Supported Formats: Modern WebP, AVIF, JPEG, PNG.
  • Access Control: Public Read (anyone can see products), Admin-Only Write/Delete.
👤 Profile Pictures (PFPs) Requirements
  • Database Schema: Stored in users.avatar_url as a single TEXT string URL.
  • Aspect Ratio: Strictly 1:1 (Square: 250x250px or 400x400px), displayed in circular avatars.
  • Max Upload Size: 500 KB (very lightweight for fast navbar render).
  • Access Control: Public Read, Owner-Only Write/Update (enforced via Row Level Security).
  • Default Fallback: Initials badge or placeholder avatar if empty.

Option 1 (Top Recommendation): Supabase Storage

🏆 Why Supabase Storage is the Ultimate Choice for NovaCart

Because NovaCart already uses Supabase PostgreSQL for authentication, users, products, and orders, Supabase Storage is the cleanest, most secure, and most cohesive solution. It integrates directly with Postgres Row Level Security (RLS), gives you 1GB of free storage on a global CDN, and allows direct client uploads without bogging down your PHP server!

Step 1: Create Storage Buckets with SQL

Execute this SQL in your Supabase SQL Editor to create the two required buckets: product-images and avatars, along with bulletproof Row Level Security policies:

Supabase SQL Editor 
-- 1. Create Public Storage Buckets
INSERT INTO storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
VALUES 
  ('product-images', 'product-images', true, 5242880, ARRAY['image/jpeg', 'image/png', 'image/webp', 'image/avif']),
  ('avatars', 'avatars', true, 2097152, ARRAY['image/jpeg', 'image/png', 'image/webp'])
ON CONFLICT (id) DO UPDATE SET
  public = EXCLUDED.public,
  file_size_limit = EXCLUDED.file_size_limit,
  allowed_mime_types = EXCLUDED.allowed_mime_types;

-- 2. Enable RLS on storage.objects
ALTER TABLE storage.objects ENABLE ROW LEVEL SECURITY;

-- 3. Policy: Anyone can view product photos and avatars (Public Read)
CREATE POLICY "Public Access Products" ON storage.objects
  FOR SELECT USING (bucket_id = 'product-images');

CREATE POLICY "Public Access Avatars" ON storage.objects
  FOR SELECT USING (bucket_id = 'avatars');

-- 4. Policy: Allow authenticated users to upload avatar to their own folder
CREATE POLICY "User Avatar Upload" ON storage.objects
  FOR INSERT WITH CHECK (
    bucket_id = 'avatars' 
    AND (auth.uid() = owner OR auth.role() = 'authenticated')
  );

-- 5. Policy: Allow users to update/delete their own avatar
CREATE POLICY "User Avatar Update" ON storage.objects
  FOR UPDATE USING (bucket_id = 'avatars' AND auth.uid() = owner);

CREATE POLICY "User Avatar Delete" ON storage.objects
  FOR DELETE USING (bucket_id = 'avatars' AND auth.uid() = owner);

-- 6. Policy: Admin Product Images Upload (or via service_role API)
CREATE POLICY "Admin Upload Products" ON storage.objects
  FOR INSERT WITH CHECK (bucket_id = 'product-images');

CREATE POLICY "Admin Delete Products" ON storage.objects
  FOR DELETE USING (bucket_id = 'product-images');

Step 2: React Upload Code Implementation

Here is the ready-to-use React component that uploads files directly to Supabase Storage and returns the public CDN URL:

JavaScript (React Upload Service) 
import { createClient } from '@supabase/supabase-js';

// Initialize Supabase Client with anon key (Safe for browser)
const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY
);

/**
 * Upload an avatar to Supabase Storage
 * @param {File} file - The file from input type="file"
 * @param {string} userId - Current authenticated user ID
 * @returns {Promise} Public CDN URL of uploaded avatar
 */
export async function uploadUserAvatar(file, userId) {
  // Validate file type
  if (!file.type.startsWith('image/')) {
    throw new Error('Please select an image file (JPEG, PNG, WebP)');
  }

  // 1. Generate unique file path: avatars/{userId}-{timestamp}.webp
  const fileExt = file.name.split('.').pop();
  const filePath = `${userId}-${Date.now()}.${fileExt}`;

  // 2. Upload to Supabase 'avatars' bucket
  const { data, error } = await supabase.storage
    .from('avatars')
    .upload(filePath, file, {
      cacheControl: '3600',
      upsert: true // Overwrite previous avatar
    });

  if (error) throw error;

  // 3. Get Public CDN URL
  const { data: { publicUrl } } = supabase.storage
    .from('avatars')
    .getPublicUrl(filePath);

  return publicUrl;
}

/**
 * Upload a product image to Supabase Storage
 * @param {File} file - Product image file
 * @returns {Promise} Public CDN URL
 */
export async function uploadProductImage(file) {
  const cleanName = file.name.replace(/[^a-zA-Z0-9.]/g, '_');
  const filePath = `products/${Date.now()}_${cleanName}`;

  const { data, error } = await supabase.storage
    .from('product-images')
    .upload(filePath, file, { cacheControl: '31536000' });

  if (error) throw error;

  const { data: { publicUrl } } = supabase.storage
    .from('product-images')
    .getPublicUrl(filePath);

  return publicUrl;
}

Option 2: Cloudinary (Best for Dynamic AI Transformations & Avatars)

✨ Why Choose Cloudinary?

Cloudinary is the world-leading media platform for eCommerce. Its standout feature is automatic AI face detection for user profile pictures (so faces are never cut off in circular avatars) and automatic format selection (serves AVIF to Chrome, WebP to Firefox, and JPEG to legacy Safari).

Direct Browser Upload using Unsigned Preset

JavaScript (React) 
/**
 * Direct upload to Cloudinary using an Unsigned Upload Preset
 */
export async function uploadToCloudinary(file, folder = 'novacart_products') {
  const CLOUD_NAME = 'your_cloud_name';
  const UPLOAD_PRESET = 'novacart_unsigned_preset'; // Created in Cloudinary settings

  const formData = new FormData();
  formData.append('file', file);
  formData.append('upload_preset', UPLOAD_PRESET);
  formData.append('folder', folder);

  const res = await fetch(`https://api.cloudinary.com/v1_1/${CLOUD_NAME}/image/upload`, {
    method: 'POST',
    body: formData
  });

  const data = await res.json();
  if (!res.ok) throw new Error(data.error?.message || 'Upload failed');

  // Returns optimized URL:
  return data.secure_url;
}

Option 3: Cloudflare R2 / AWS S3 (Best for Enterprise & Zero Egress)

🗄️ Cloudflare R2: S3-Compatible with ZERO Bandwidth Fees

AWS S3 charges you every time an image is downloaded (egress fee). Cloudflare R2 has $0 egress fees and provides an S3-compatible API.

Secure Presigned URL Workflow:

  1. Frontend asks PHP backend: "I want to upload a product image named shoes.webp".
  2. PHP backend verifies user is an Admin, generates a temporary Presigned PUT URL valid for 5 minutes, and sends it back.
  3. Frontend uploads the image directly to S3 / Cloudflare R2 using standard PUT.
  4. Frontend saves the permanent image URL in the database. Your PHP server never handles the heavy image bytes!

Option 4: Local Server Storage via PHP Backend

💻 Hosting Uploads on your Own Linux Server

If you do not want to use any third-party cloud service, you can have your PHP backend receive multipart file uploads, validate them, and store them inside backend/public/uploads/.

🚨
CRITICAL SECURITY WARNING: If an attacker uploads a malicious PHP script (e.g. hack.php) into an uploads directory that executes PHP, they can take over your entire server! You MUST enforce the security controls below:

1. Secure PHP Upload Endpoint

PHP (backend/src/Controllers/UploadController.php) 
<?php
namespace NovaCart\Controllers;

use NovaCart\Config\Security;

class UploadController {
    public static function handleUpload(): void {
        header('Content-Type: application/json');

        // 1. Verify user is authenticated
        // $user = Security::getAuthenticatedUser();

        if (empty($_FILES['image'])) {
            http_response_code(400);
            echo json_encode(['error' => 'No image file uploaded']);
            return;
        }

        $file = $_FILES['image'];

        // 2. Check for upload errors
        if ($file['error'] !== UPLOAD_ERR_OK) {
            http_response_code(400);
            echo json_encode(['error' => 'Upload failed with error code ' . $file['error']]);
            return;
        }

        // 3. Limit file size (Max 5MB)
        if ($file['size'] > 5 * 1024 * 1024) {
            http_response_code(400);
            echo json_encode(['error' => 'File exceeds 5MB size limit']);
            return;
        }

        // 4. Validate REAL MIME type using finfo (Never trust client filename!)
        $finfo = new \finfo(FILEINFO_MIME_TYPE);
        $mime = $finfo->file($file['tmp_name']);

        $allowedMimes = [
            'image/jpeg' => 'jpg',
            'image/png'  => 'png',
            'image/webp' => 'webp'
        ];

        if (!array_key_exists($mime, $allowedMimes)) {
            http_response_code(400);
            echo json_encode(['error' => 'Invalid file format. Allowed: JPG, PNG, WEBP']);
            return;
        }

        $extension = $allowedMimes[$mime];

        // 5. Generate unguessable random UUID filename
        $filename = bin2hex(random_bytes(16)) . '.' . $extension;
        $uploadDir = __DIR__ . '/../../public/uploads/';

        if (!is_dir($uploadDir)) {
            mkdir($uploadDir, 0755, true);
        }

        $destination = $uploadDir . $filename;

        // 6. Move uploaded file
        if (!move_uploaded_file($file['tmp_name'], $destination)) {
            http_response_code(500);
            echo json_encode(['error' => 'Failed to save uploaded file']);
            return;
        }

        // 7. Return public URL
        $baseUrl = (isset($_SERVER['HTTPS']) ? 'https://' : 'http://') . $_SERVER['HTTP_HOST'];
        $publicUrl = $baseUrl . '/uploads/' . $filename;

        echo json_encode([
            'status' => 'success',
            'url' => $publicUrl,
            'filename' => $filename,
            'mime' => $mime,
            'size' => $file['size']
        ]);
    }
}

Client-Side Image Compression & Optimization (Speed Up Uploads by 90%)

Modern smartphone cameras take 12MB to 20MB photos. If users upload raw photos without client compression, it wastes user mobile data, takes 15 seconds to upload, and fills up your server storage! Use this built-in Canvas compression function that shrinks images to under 250KB in under 50ms right in the browser:

JavaScript (frontend/src/utils/compressor.js) 
/**
 * Ultra-fast browser image compression using HTML5 Canvas
 * @param {File} file - Original file from input
 * @param {Object} options - { maxWidth: 1000, maxHeight: 1000, quality: 0.82 }
 * @returns {Promise} Compressed WebP/JPEG blob
 */
export function compressImage(file, { maxWidth = 1000, maxHeight = 1000, quality = 0.82 } = {}) {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.readAsDataURL(file);

    reader.onload = (event) => {
      const img = new Image();
      img.src = event.target.result;

      img.onload = () => {
        let width = img.width;
        let height = img.height;

        // Maintain aspect ratio while resizing
        if (width > height) {
          if (width > maxWidth) {
            height = Math.round((height * maxWidth) / width);
            width = maxWidth;
          }
        } else {
          if (height > maxHeight) {
            width = Math.round((width * maxHeight) / height);
            height = maxHeight;
          }
        }

        const canvas = document.createElement('canvas');
        canvas.width = width;
        canvas.height = height;

        const ctx = canvas.getContext('2d');
        ctx.imageSmoothingEnabled = true;
        ctx.imageSmoothingQuality = 'high';
        ctx.drawImage(img, 0, 0, width, height);

        // Convert to lightweight WebP format
        canvas.toBlob(
          (blob) => {
            if (!blob) return reject(new Error('Canvas conversion failed'));
            resolve(blob);
          },
          'image/webp',
          quality
        );
      };

      img.onerror = (err) => reject(err);
    };

    reader.onerror = (err) => reject(err);
  });
}

High-Security Architecture Overview

In standard insecure web apps, client applications communicate directly with Supabase with client-side keys or risk exposing privileged Service Role credentials in frontend code bundles. In NovaCart's enterprise-grade setup:

🛡️
Backend Gateway Mediation
All mutations and sensitive queries flow through the PHP API gateway, enforcing rate limiting, input sanitization, and JWT verification.
🔒
Service Role Isolation
The high-privilege SUPABASE_SERVICE_ROLE_KEY is kept strictly on the PHP backend environment and NEVER exposed to browsers.
🗄️
Row Level Security (RLS)
PostgreSQL tables and storage buckets have granular row-level and object-level permissions, preventing unauthorized access.
